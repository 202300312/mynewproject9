# 모두를 위한 학교 콘서트장 만들기 — SQLite 협업 실행판

## 실행

```bash
python -m pip install -r requirements.txt
python -m streamlit run run.py
```

접속: http://localhost:8501 (학교 서버에 배포한 경우 해당 서버 주소)

## 달라진 점

- 로그인: 한 줄 제목, SQLite 기반 회원가입 및 인증
- 화면: 90% 배율, HTML 내 단일 스크롤, ChatGPT 방식 왼쪽 고정 사이드바와 하단 로그아웃
- 색상: 기본 HTML 활동·계산 내용은 밝은 색을 유지하고, 외부 Streamlit 화면은 운영체제 다크모드에 대응
- 모둠: 회원 선택 후 초대하여 모둠 생성. 초대 수락 후 공동 기록 사용
- SQLite에 사용자별 개인 기록과 모둠별 공동 기록 분리 보관
- 변경 내용은 수 초 간격으로 읽어오며, 다른 항목 변경은 가능한 한 병합

## 협업 순서

1. 각 학생이 개별 가입 후 로그인합니다.
2. 왼쪽 `모둠 협업` 메뉴에서 모둠장 학생이 `새 모둠 만들기`를 선택합니다.
3. 이미 등록된 회원을 체크하고 모둠을 생성하면 초대가 발송됩니다.
4. 초대된 학생은 자기 계정에서 `모둠 협업` 메뉴의 초대를 수락합니다.
5. `작업 공간 변경`에서 모둠을 선택하면 모둠원 모두 동일한 입력 기록을 보게 됩니다.
6. 입력값은 수정 후 약 0.5초 뒤 서버에 저장됩니다. 다른 학생의 수정 사항은 약 3초마다 확인하며 화면이 잠시 비활성 상태일 때 다시 표시됩니다.

## 주의사항

- 원본 학생용 웹앱의 에너지 계산과 PDF 출력은 기존대로 유지합니다.
- 동일 데이터의 같은 입력칸을 동시에 수정하면 마지막으로 저장된 값이 우선합니다.
- 서로 다른 항목은 JSON 필드 단위로 병합합니다. 동시에 같은 표의 행을 추가/삭제하면 충돌할 수 있으니 모둠에서 작업을 나누세요.
- 웹앱 표시용 90% 배율은 브라우저/OS에 따라 약간 달라질 수 있습니다.
- SQLite DB 경로는 `CONCERT_DB_PATH` 환경변수로 설정할 수 있습니다. 배포 시 **반드시 영구 볼륨**에 DB 파일을 저장하세요.
- 동시접속이 많은 대규모 수업에서는 PostgreSQL 등 서버형 DB가 적합할 수 있습니다.
- 비밀번호는 PBKDF2 해시로 저장합니다. 운영 환경에서 HTTPS, 접근 통제, 백업, 학교의 개인정보 보호 지침을 적용하세요.
- `myproject.db` 파일을 보존/백업해야 회원 정보와 기록이 유지됩니다.
- 앱을 업데이트해도 DB 파일을 삭제하지 마세요.
- 교실 실습 시 교사가 시범 계정과 별도 실제 계정으로 협업 동작을 확인하는 것이 좋습니다.

## 이번 버전 변경점
- 신규등록은 이름, 아이디(학번: 숫자 4~15자리), 비밀번호, 비밀번호 확인을 입력합니다.
- 학번은 입력 중 서버 SQLite에 중복 여부를 조회하며 오른쪽에 표시합니다.
- 비밀번호 확인란은 입력 즉시 브라우저에서 일치 여부를 표시합니다.
- 모둠 정보(조 이름·조원 이름) 작성란은 **모둠 협업** 탭에서 이용합니다.
- 학번은 UNIQUE 제약으로 최종 가입 시에도 중복 등록되지 않습니다.
- 기존 데이터베이스에 영어 아이디로 가입한 사용자는 기존 계정을 사용할 수 있습니다. 신규 가입부터 학번 숫자 제한이 적용됩니다.

## 화면 수정 사항 (2026-11-17)

- 모둠 협업 메뉴를 첫 메뉴로 표시합니다. 탭을 초기 HTML에 배치하여 메뉴 클릭 시 패널이 안정적으로 열리도록 수정했습니다.
- 가입 가능 학번인 경우 우측 상태 메시지는 표시하지 않습니다. 이미 가입된 학번 경고는 유지합니다.


## 새 기능: 화면을 새로고침하지 않는 공동 편집

- 기존의 3초 주기 전체 `iframe.srcdoc` 재생성을 제거했습니다.
- SQLite의 변경 버전이 감지되면 로컬 저장된 변경 데이터만 갱신하고 기존 입력 컴포넌트에 반영합니다.
- 입력 중이거나 선택한 입력칸에 포커스가 있으면 원격 반영을 잠시 보류합니다. 입력칸 밖을 클릭하면 최신 변경을 반영합니다.
- 탭 위치, 현재 스크롤, PDF 출력 및 모둠 협업 화면은 그대로 유지됩니다.
- 같은 항목을 동시에 변경했을 때는 기존과 동일하게 마지막 저장값이 우선합니다.
- 새로 모둠에 가입하거나 개인 기록/모둠 기록으로 작업 공간을 전환할 때만 앱 화면이 새로 생성될 수 있습니다.


## 환경 2차시·기술가정 탭 표시 복구
환경 1차시 종료 지점의 불필요한 HTML 닫는 태그를 삭제하여 모든 차시 패널이 탭 컨테이너 내부에 표시되도록 바로잡았습니다. 기존 SQLite와 새로고침 없는 동기화 방식은 유지합니다.


## 이번 수정 사항
- 회원가입 성공 시 확인 메시지를 화면에 표시합니다.
- 모둠 협업 메뉴에서 모둠명, 활동 주제, 초대할 회원을 한 번에 입력합니다.
- 개인 기록 작업 공간은 제거하고, 모둠에 가입해야 학습 탭을 사용할 수 있습니다.
- SQLite 트리거 및 가입 로직으로 한 회원이 여러 활성 모둠에 들어가는 것을 방지합니다.
- 초대받은 회원이 이미 다른 모둠에 가입한 경우 초대를 수락할 수 없습니다.
- 이전 DB에 이미 여러 모둠에 가입한 회원이 있다면 데이터를 자동 삭제하지 않습니다. 관리자가 중복된 소속을 정리해야 합니다.
- 모둠장은 현재 모둠을 탈퇴할 수 없으므로 관리자가 모둠장 이전/모둠 해체를 지원해야 합니다.

### 기존 SQLite 데이터베이스를 이어서 사용할 때
`myproject.db` 파일을 **백업한 후** 새 코드로 실행하세요. 기존에 한 학생이 두 모둠 이상에 이미 활성 가입한 데이터가 있는 경우 이 버전은 기존 소속을 임의로 삭제하지 않습니다. 추가 중복 가입은 DB 트리거로 막지만, 과거 중복 소속은 관리자가 직접 확인해 정리해야 합니다.
